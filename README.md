# EventMatch KZ

**EventMatch KZ** — MVP для подбора event-подрядчиков в Казахстане, созданный для
Hack Alem AI. Организатору свадьбы, тоя, корпоратива или другого мероприятия
нужно быстро найти исполнителей, которые работают в нужном городе, свободны в
выбранную дату и подходят по бюджету, формату, языку и длительности. Сервис
принимает эти параметры и показывает до трёх карточек подрядчиков.

> **Состояние MVP:** интерфейс можно показать на встроенных демонстрационных
> данных. Backend реализует фильтрацию и ранжирование, но для работы с реальными
> профилями ему нужен исходный JSONL-файл, которого пока нет в репозитории.
> Объяснения в реальном ответе backend ещё не генерируются моделью.

## Что реализовано

- Форма заказа: город, дата, тип мероприятия, категория подрядчика, бюджет,
  необязательные язык и длительность.
- До трёх карточек с именем, категорией, городом, стартовой ценой и полем
  «Почему этот».
- Отдельные состояния интерфейса: загрузка, результат, отсутствие категории
  в городе, отсутствие совпадений после фильтров и ошибка запроса.
- `POST /api/recommend` на FastAPI: фильтрация по данным подрядчиков,
  детерминированное ранжирование и указание причин, по которым никто не подошёл.
- Демонстрационный режим фронтенда с локальными мок-профилями. Он включён по
  умолчанию, поэтому интерфейс можно проверить без датасета и backend.

## Как работает решение

1. Пользователь задаёт параметры мероприятия в веб-форме.
2. Фронтенд отправляет `POST /api/recommend`. В демонстрационном режиме ответ
   формируется из локальных мок-данных; в реальном режиме запрос через прокси
   Next.js поступает в FastAPI.
3. Backend сначала находит подрядчиков выбранных города и категории. Затем
   исключает тех, кто не работает с нужным форматом, занят на дату, дороже
   бюджета, не владеет выбранным языком или не подходит по длительности.
4. Оставшиеся профили сортируются по фиксированному скору: совпадение слов
   категории и формата с описанием, близость стартовой цены к бюджету и `id`
   при равенстве. В ответ попадают первые три.
5. Интерфейс показывает карточки или объясняет, почему результатов нет.
   `total_candidates` отражает число подрядчиков в городе и категории **до**
   остальных фильтров.

`no_category` означает, что в городе нет подрядчиков выбранной категории.
`no_match` означает, что такие подрядчики есть, но каждый не прошёл хотя бы
один из фильтров. `ok` означает, что найден хотя бы один подходящий профиль.

## Технологии и архитектура

| Компонент | Технологии | Назначение |
| --- | --- | --- |
| [Фронтенд](frontend/) | TypeScript, Next.js 16, React 19, Tailwind CSS 4, компоненты shadcn/ui | Форма заказа, карточки, состояния результата и демонстрационные моки |
| [Backend](backend/) | Python 3.10+, FastAPI, Pydantic 2, Uvicorn | Контракт API, загрузка JSONL, фильтрация и ранжирование |
| Данные | JSON Lines (`.jsonl`) | Профили подрядчиков; после запуска хранятся в памяти backend |

```text
Браузер → Next.js → /api/recommend → FastAPI → профили из JSONL
                     ↘ локальные моки при NEXT_PUBLIC_USE_MOCKS=true
```

Фронтенд обращается к `/api/recommend` на своём домене. В реальном режиме
Next.js перенаправляет `/api/*` на адрес из `BACKEND_URL` (по умолчанию
`http://localhost:8000`). Backend читает датасет один раз при старте;
изменения файла требуют перезапуска сервера.

**AI-модель в текущей версии не вызывается.** Интеграция с OpenAI для
индивидуальных объяснений запланирована следующим этапом; одного имени
`OPENAI_API_KEY` в [.env.example](backend/.env.example) для её работы недостаточно.

## Установка и запуск

Нужны Python 3.10+ и Node.js с npm. Команды ниже приведены для PowerShell;
запускайте backend и frontend в разных терминалах из корня репозитория.

### Быстрая демонстрация интерфейса на мок-данных

```powershell
cd frontend
npm ci
npm run dev
```

Откройте `http://localhost:3000`. По умолчанию
`NEXT_PUBLIC_USE_MOCKS=true`, поэтому backend и JSONL-файл для этого режима
не нужны. Карточки и объяснения здесь демонстрационные.

### Запуск с реальным API

1. Поместите `hackathon-dataset-anonymized.jsonl` в `backend/data/`.
2. В первом терминале установите зависимости и запустите backend:

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn main:app --reload --host 127.0.0.1 --port 8000
```

3. Во втором терминале запустите фронтенд в режиме реального API:

```powershell
cd frontend
npm ci
$env:NEXT_PUBLIC_USE_MOCKS = "false"
$env:BACKEND_URL = "http://localhost:8000"
npm run dev
```

Откройте `http://localhost:3000`. Документация backend доступна по адресу
`http://localhost:8000/docs`. Если JSONL отсутствует, пуст или содержит
некорректный профиль, backend остановится при старте с сообщением об ошибке.

## Как проверить решение

**Сценарий для жюри без дополнительных файлов:** запустите быстрый
демонстрационный режим, откройте форму и выберите Алматы, тип «той», категорию
«ведущий», бюджет 300 000 ₸. Отправьте запрос: появятся карточки подходящих
подрядчиков. Затем укажите категорию, отсутствующую в выбранном городе,
чтобы увидеть состояние `no_category`, или поставьте бюджет 1 ₸ для проверки
`no_match`. Переключатель мок-ответов в шапке позволяет отдельно показать
все три состояния.

**Проверка реального backend после добавления датасета:**

```powershell
$body = @{
    city = "Алматы"
    event_date = "2026-10-01"
    event_type = "свадьба"
    category = "ведущий"
    budget_kzt = 300000
    duration_hours = 4
    language = "русский"
} | ConvertTo-Json

Invoke-RestMethod -Uri "http://localhost:8000/api/recommend" `
    -Method Post -ContentType "application/json; charset=utf-8" -Body $body
```

Ответ содержит `status`, `message`, `total_candidates` и массив `results`.
Каждая карточка содержит `id`, `name`, `category`, `city`, `price_from_kzt`
и `explanation`. Конкретный статус зависит от содержимого датасета и даты.
Для повторной проверки одинаковый запрос должен дать тот же порядок карточек.

## Данные и интеграции

Для реального подбора ожидается предоставленный организаторами
`backend/data/hackathon-dataset-anonymized.jsonl` с 66 анонимизированными
профилями (один JSON-объект на строку). Профиль содержит идентификатор,
псевдоним, категории, город, стартовую цену в тенге, форматы мероприятий,
языки, максимальную длительность, занятые даты и текстовое описание.
Флаги `synthetic`, `city_imputed`, `price_imputed` читаются, но сейчас не
влияют на подбор.

Демонстрационные профили находятся в [моках фронтенда](frontend/src/lib/mocks.ts)
и не являются исходным датасетом из 66 записей. Внешние API и сервисы в
текущем режиме не вызываются; OpenAI API пока не подключён.

## Ограничения текущей версии

- Исходного JSONL в репозитории пока нет: реальный backend без него не стартует.
- Поле `explanation` в ответе backend содержит `заглушка`. Подробные объяснения
  в демонстрационном режиме формируются локальным кодом фронтенда.
- Скор использует совпадение начал слов в описании и близость цены к бюджету;
  семантического поиска и AI-ранжирования пока нет.
- Нет базы данных, бронирования, подтверждения доступности исполнителем и
  обновления профилей без перезапуска backend.
